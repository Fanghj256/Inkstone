# 可选：语义检索层

> 这一页讲一个**可选项**，不是项目的一部分。不装它，inkstone 照常工作。

## 为什么会有这一层

`rg` 很强，但它有个前提：**你得记得那个词**。

- 记得"agent 的记忆存在哪"，搜 `记忆` 就能命中。
- 只记得"好像有篇文章讲模型为什么老忘事"，`rg` 就没辙了——原文里可能一个"忘"字都没有。

第二种情况会随库变大而变多。这就是语义检索要补的洞：**把"找词"换成"找意思"**。

## 为什么是 SAG2

因为它是目前少数不违反本项目两条铁律的检索方案。

| 方案 | 索引阶段做什么 | 和本项目冲突吗 |
|---|---|---|
| 向量 RAG | 切块 + embedding，存进向量库 | 要复制一份原文，产生第二事实源 |
| GraphRAG | 大模型抽三元组建全局图 | 要模型改写原文，贵且难增量 |
| LLM Wiki | 模型把资料编译成 wiki 页 | 直接改写原文，违反"不许 AI 改它" |
| **SAG2** | **只建 BM25 关键词倒排索引** | **不生成内容、不复制原文** |

一句话：**它在原文之上加一层目录，不加一层副本。**

而且这层目录可丢弃——几万字重建一次不到一秒，删掉不心疼。所以它更像"临时打开一个索引"，而不是"引入一个长期依赖"。

## 怎么接

**桌面版（最省事）**

装 [SAG-Wiki](https://github.com/Zleap-AI/SAG-Wiki)，添加文件夹指向 `002-references/raw`。34 篇、45 万字，实测 791 ms 建完。

**命令行 + Agent（推荐）**

```bash
npm install -g @zleap-ai/sag
sag add "D:\my-kb\002-references\raw" --types md
sag check "D:\my-kb\002-references\raw"
sag "视频抽帧为什么不能只按固定间隔" "D:\my-kb\002-references\raw" -m 5
```

接给 agent：

```bash
sag install opencode      # 或 claude-code / codex
```

装完 agent 会拿到一个 `sag` Skill，知道什么时候该搜、怎么读回来。**agent 自己问答，不需要再给 SAG 配一个 LLM**——它只负责检索，答案由 agent 的模型生成。

`--types md` 别省：不加的话 `note.html` 和 `frames/*.jpg` 也会被当文档扫进去。

## 实测数据

34 篇、45 万字（2026-11-10）：

| 项目 | 结果 |
|---|---|
| 建索引 | 791 ms |
| 索引体积 | 1.85 MB，存在系统应用数据目录，**不在库里** |
| 换个说法的问题 | 3/3 命中（同一批问题字面搜索 0 条） |
| 单次查询耗时 | 2.4–7.4 秒 |

三个"记得大概意思但记不清词"的问题，`sag` 全中，`rg` 全空。这就是它真正买来的东西，其余都是副作用。

## 四条边界

**一、JEV 是硬依赖，不会降级。**

不配决策模型（JEV），`sag "问题"` 直接报错退出，**不会**退化成关键词检索。`-F` / `-E` 能跑，但那就是 grep，没有语义能力。桌面版和 CLI 共用这份配置。

**二、它不会告诉你"没找到"。**

问库里没有的东西，它照样返回 4–9 条"沾边但不相关"的段落，而且 JSON 里没有相关性分数可以卡阈值。对人是小事——一眼看出不对；**对 agent 是幻觉入口**，模型可能把"文档提到 PostgreSQL"当成"回答了 PostgreSQL 的问题"。接 agent 时要在提示里写明：命中但不相关就说不确定。

**三、配了 JEV，片段会离开本机。**

原文件留在本地，但深度检索和问答会把问题、文档片段、上下文发给你配置的服务。本项目第一段立的旗子是 "No cloud"——**这一条在配了 JEV 之后不成立**。要用就明说，别装作没这回事。

**四、索引会往被索引目录里写字。**

`sag add` 会在目标目录生成 `.sagignore`（存扩展名等索引选项）。它不该进 git，
知识库和 Inkstone 两个仓库的 `.gitignore` 都已经排除了它。

## 该不该装

看库的规模：

- **几百篇以内**：`rg` 够用，装了收益不明显。
- **上千篇之后**：开始出现"记得有、搜不到"，这时候装。
- **要给 agent 用**：现在就值得，省掉的是 agent 反复翻文件的时间。

一条经验：**`rg` 当默认，`sag` 当兜底**。毫秒级和秒级差两个数量级，日常检索没必要为语义付这个代价。
