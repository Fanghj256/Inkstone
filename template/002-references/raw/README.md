# 002-references/raw · 一手原文库

**这里只有别人写的东西，且必须是原文。** 任何模型摘要都不许进来。

## 为什么按来源分子目录

严格按"扁平四层"的话，这里不该再分层。我还是分了，原因有三个：

1. **排障**：某个源被反爬挡住了，一眼就能看出是 `zhihu/` 空了，而不是在一堆文件里猜。
2. **清理**：想整体丢弃某个源的抓取结果，`rm -r raw/zhihu` 一条命令，不用担心误伤。
3. **检索**：`rg "关键词" raw/x/` 能把范围收窄到一类来源，对小样本判断很有用。

如果你更想要绝对扁平，把 `inbox.py` 里的目录部分改成固定写到 `raw/` 就行，
来源信息在 frontmatter 的 `source:` 字段里本来就有。

## 每个文件的头部长这样

```yaml
---
url: https://example.com/post        # 规范化后的原始链接（去掉 utm 之类）
title: 文章标题
source: x                            # x / github / zhihu / wechat / xiaohongshu / web / video
author: 作者或公众号名
fetched_at: '2026-11-06T18:57:34+08:00'
fetched_via: ego-browser/article     # 用哪个提取器抓的，排障时有用
chars: 13118                         # 正文字数，判断抓没抓全
---
```

文件名末尾那 8 位是 URL 指纹，用来去重。同一个链接再发一次会被跳过。

## 什么时候该怀疑

- `chars` 不到 300：大概率被拦了，看 `../failed/` 里有没有对应记录
- 正文开头是一堆导航文字：提取器选错了，把它挪到 `failed/` 再重抓
- 图片全丢：这是纯文本库的固有限制，需要图就保留原链接

`../files/` 放你直接发过来的 PDF、Word、转写稿；`../failed/` 放抓失败的原始记录。
